# 第二增长曲线：证据驱动的探索检查

来源：第7章正文已连续读完至小结，图表待视觉核对；章节定位见包内 [图书证据索引](book-evidence.md) 的第7章记录及原书7.1—7.4节。此页问题与六步衔接属于将作者方法转成对话的Skill编排。**不是建议所有业务都转型，也不保证新方向成功。**

## 什么时候启动

用户认为成熟业务停滞、原有策略边际作用变小时，先核对三组证据（7.1；C71-1—3）：

1. **产品价值**：下一轮迭代还能解决哪些真实问题，预计影响谁，有何证据？
2. **市场与竞争**：剩余目标用户是否仍足够多，为什么尚未进入，竞争究竟挤压了哪里？
3. **外部变化**：技术、政策、资本或经济条件正在发生什么变化，哪些已发生，哪些只是期待？

把每项写成“证据、判断、未知项”。未知不是没有空间；短期波动、团队疲惫和单次实验失败，不足以证明第一曲线结束。作者提出在现有空间不足时探索第二曲线，本Skill不据此自动建议放弃当前业务。

## 五类候选路径

| 路径（7.2） | 优先问的一句话 | 至少需要的证据 |
| --- | --- | --- |
| 现有用户的新需求 | 沿生命周期、使用链路和场景看，同一批用户还有什么问题没解决？ | 需求路径、替代方案、真实行为及与原产品的关联（C74-1） |
| 复制到新地域 | 原有模式在新地域的哪些条件仍成立？ | 需求与供给条件，以及关键差异（C74-2） |
| 新用户群体 | 还有谁已在用；现功能是否满足；补能力是否有增长价值？ | 真实使用、人群需求、现有能力缺口（C74-3） |
| 新服务模式 | 换一种交付或付费方式是否解决了现有阻碍？ | 用户价值、可交付性、资源与经济约束（C74-4） |
| 技术升级 | 新技术具体使哪项价值更可行？ | 可验证能力与用户价值，不能只靠技术热度（C74-5） |

每个候选必须解释它改变了什么。普通功能优化或换一条渠道不自动构成第二曲线；案例公司名称也不能替代本业务证据。

## 按7.4组织一次探索

1. 选一条最有证据的路径，写出用户当前任务、阻碍和已有替代方案。
2. 用需求路径标出机会：发生于哪个生命周期阶段、操作环节或场景，与原产品有什么关系。
3. 检查现有能力能否满足；若需要新功能、新服务或地域适配，明确必要变化与成本。
4. 写出可被证伪的需求假设和下一项验证；区分用户已表现的行为、团队推断和对未来的期待。

上述四项是基于作者7.4提问的执行整理，不是作者额外命名的“四步法”。只选择与当前候选有关的字段，不机械画满所有路径。

## 回到六步主链

这部分是Skill的衔接编排：

- 对尚无产品、商业模式或真实需求证据的新方向，先标前提缺口，不直接承诺规模化增长。
- 已有可验证产品/服务后，按六步重新界定目标价值、主要驱动、增长公式与杠杆、候选行为阈值、策略及验证方案。
- 将旧业务经验写成待验证假设，不直接复制旧指标、阈值、渠道效果或组织配置。
- 输出少数候选与下一项验证，不把五条路径展开成必须同时执行的五项工程。

## 案例引用边界

- 苹果、TikTok、任天堂、Adobe、WPS均按作者的历史/业务案例引用，不冒充本轮独立核实的当前公司事实。
- 不迁移TikTok收购、改名和DAU的潜在混淆；不以性别或年龄标签推断用户喜好。
- 授权转订阅、基础免费增值付费不是普遍有效的处方，短期和长期结果均需观察。
- 原书对WPS部分订阅成效和WPS AI增长仍属待观察或期待，不能写成既成业绩。
- 技术升级不是增长保证，案例相关描述不能替代当前业务的需求和效果验证。

HTML可输出一张简表：“候选方向—需求证据—与现有业务关联—必要变化—关键未知—下一项验证”，缺证据填“待验证”。是否继续第一曲线、并行试新方向或进一步投入，应由这些证据支持，不自动导向转型。
