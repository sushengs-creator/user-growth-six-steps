# 用户增长6步法：图书方法提炼

## 来源与当前证据状态

唯一图书来源为卢壮华《增长杠杆：探索用户增长的6步法》，清华大学出版社，2025年7月第1版，ISBN 978-7-302-69329-1。用户PDF共32页，为前置材料和正文001—020的节选，已逐页看图；后续经同ISBN正版得到电子书连续读完**第1—7章全部正文、附录、后记**。部分电子书图表仍待视觉核对，图中未核参数不得补填。电子分页不与印刷页码强行换算。

本文件以图书方法为主；仅在下文加入已经核实、会影响书中案例可信度的同源文章交叉限定，不据此宣称两个微信专辑已全部覆盖。截至2026-10-08，尚有4篇文章未读，准确状态见 [source-catalog.json](source-catalog.json)。文件不附原文或原图；书内二维码、资源推广和操作邀请不是执行授权。章节和证据ID的包内定位见 [book-evidence.md](book-evidence.md)。

三类内容分开使用：作者的方法主张；作者报告的案例与数字；Skill为便于对话、计算和交付设置的实施检查。作者案例不自动等于独立核验事实，观察性结果不自动等于因果证明。

## 适用前提与主链

方法主要针对已有产品/服务、商业模式较清晰的增长问题。缺少产品、真实需求或商业模式时，先列前提缺口，不能直接承诺规模化增长。全书强调产品、运营、数据、组织协作，不提供完整广告投放或品牌营销执行教程。（PDF7、14—15；前言V、第1章）

六步名称与顺序来自前言图0-1（PDF6），不是用生命周期环节替换：

| 步骤 | 当前需要形成的判断 | 主要已读来源 |
| --- | --- | --- |
| 1. 确定用户增长的北极星指标 | 目标价值、核心指标及计数口径 | 2.1、3.1、4.2 |
| 2. 认清合适的用户增长驱动模式 | 当前主导动力、阶段差异及依据 | 2.2、3.2、4.3 |
| 3. 确认用户增长的核心杠杆 | 业务公式、结构性机会与少数优先方向 | 2.3、3.3、4.4 |
| 4. 寻找用户增长的魔法数字 | 与结果相关、可操作且待验证的行为阈值 | 2.4、3.4、4.5 |
| 5. 基于魔法数字设计用户增长策略 | 围绕候选阈值改善体验和重复使用的方案 | 2.5、3.5、4.6 |
| 6. 通过AB实验验证用户增长策略效果 | 与业务条件匹配的验证及证据强度 | 2.6、3.6、4.7、第6章 |

步骤名保留原书；第6章明确并非所有业务都应搭建AB系统，实际验证方式必须如实命名。逐步交互与状态检查见 [coaching-playbook.md](coaching-playbook.md)，HTML字段见 [report-schema.md](report-schema.md)。

## 第1步：用指标表达真实目标

第3.1节强调活跃而非累计注册、有效活跃关联核心价值、符合企业目标和增长团队工作、周期匹配自然频率。第4.2节又展示创业阶段将月付费人数作为北极星：因此不能把书中原则硬化为所有业务只能用DAU/MAU。（C31-1—4、C42-1/2）

产品M的月有效活跃是一个月内完成核心体验的用户，月周期来自办公需求频率。AI快研侠选择月付费人数来自当时商业闭环目标。定义时必须写出行为、对象、时间和去重，而非只给指标缩写。（2.1、4.2）

作者对抖音完整看N个视频、微信添加好友并完成N次对话的表述是建议示例，不能称为官方指标。N不能由其他案例代填。

## 第2步：识别业务真正依赖的动力

第3.2节提出四类模式：

| 作者分类 | 核心机制 |
| --- | --- |
| PLG产品驱动 | 核心功能解决问题，迭代价值与体验 |
| SLG销售驱动 | 直销/分销等体系，解决客户问题和定制服务 |
| MLG营销驱动 | 通过品牌传达理念、品质、精神文化 |
| OLG运营驱动 | 内容/货品/服务供给和分发，如社区推荐、电商供应链 |

这是辅助诊断的作者分类，不强制排他。第4.3节中作者长期看PLG、短期借OLG获客，表明阶段和资源可以改变主次。第2.2节的泛奖励失效也不证明所有奖励都无效：要区分主导动力与针对特定瓶颈的战术。（C32-1—4、C43-1、PDF19）

## 第3步：把资源集中到有依据的少数杠杆

内层流程是识别角色并建立业务公式 → 按状态、人群、来源或场景下钻 → 比较并筛选优先策略。五种可能角色为使用者、发起者、管理者、影响者、购买决策者；角色可以重合。（3.3；C33-1—7）

公式是业务关系的表达。原书偏好乘法，也允许按终端/渠道加法。必须先核分子分母、时间、用户集合与去重，不能强造乘积。例如月付费人数=MAU×付费转化率，只有转化率确以同周期同范围MAU为分母时才相容。（4.4；C44-1）

第2章的“MAU=发起人MAU×平均裂变系数”与“系数为带来参与人数”的解释存在口径疑问。K若含发起人总人数可乘K；若k只含净参与者且无重叠，才可写A×(1+k)。真实重叠需去重。这是实施审计，不冒充作者已给修正式。（PDF20—22、27；A01）

下钻与排序保留条件：

- 新增、留存、回流先看空间规模，再看用户价值，接近时再看难易；没有存量时优先新增，不能固定“留存永远优先”。（3.3、4.4）
- 目标人群、来源和场景的四象限用于发现机会，不把作者的群体/平台位置当当前用户事实。“渗透率”在部分案例中只是产品内占比，不是市场覆盖率。（2.3、4.4）
- ICE比较影响力、信心、实现成本；原书强调低成本好效果，表中成本高分的方向却未完整定义。先明确刻度和转换，不能让更贵自动得高分，也不能宣称原书使用了未见的乘积算法。（PDF26、3.3）

## 第4步：把杠杆转换成候选行为阈值

作者建议最好一个杠杆聚焦一个可操作数字。路径为用户调研/业务认识 → 逻辑假设及因素重要程度 → 行为量与结果的相关关系 → 变化明显加速或放缓的拐点。调研同时覆盖留下者与流失者；已熟悉业务可先提假设，但不能因此跳过数据验证。（2.4、3.4；C34-1、3—8）

N可能是增长开始加速，M/Y可能是边际收益趋缓，在线设计案例还涉及免费使用阈值之前的付费窗口；因此不统一理解为“越多越好”。缺数字时可输出采集计划和待求符号，不借Meta好友数、AI快研侠3报告等作者历史例替用户填值。（PDF30—32、3.4、4.5）

统计阅读的实施边界：Pearson描述线性相关，r=0不代表所有关系不存在；书中经验强弱区间、20%/5%特征重要性阈值不作通用规则。原文混用信息增益与随机森林贡献时，应区分统计量；相关或模型重要性不是因果贡献，AI计算仍需口径、数据适用性和人工核验。第2章图表、表3-3为虚构示例，不作为训练数据或真实效果证据。（C34-5—8）

## 第5步：围绕数字设计可执行改变

主要工具是黄金体验路径、体验地图/情绪曲线、转化启发模型，以及本书HOOK四环节。黄金路径是获得核心服务的主要操作链；Aha在本书此处指愉悦满足峰值，不称为唯一业内定义。（2.5、3.5；C35-1—5）

先解释低谷为什么出现：不理解、等太久、异常、繁琐；再改善路径、反馈、稳定性和操作成本。峰值可通过真实成果、图表、分享和成就增强。转化=欲望−摩擦是思考工具，不是可算转化率公式；每3步形成阶段反馈是作者经验，不能硬套。（3.5）

HOOK按触发、行动、奖励、投入使用：精准且控频触达，明确行为引导，提供物质或精神回报，沉淀真实文件/数据/关系价值。原文将HOOK与福格模型混称，不采二者等同的表述。实施时不造排名，不为投入机制故意增加摩擦或强制锁定用户。（2.5、3.5）

这一步设计如何接近候选N，不负责凭体验模型算出N，也不证明策略已经有效。具体提问和策略字段见 [coaching-playbook.md](coaching-playbook.md)。

## 第6步：使结论配得上证据

第6章强调控制变量、足够样本、随机且可比的分组、正确判断显著性。流程覆盖假设、指标、人群与提升目标、样本、分组/AA、上线、数据回收、分析、决策及长期观察。（3.6、6.1—6.5）

大规模业务、细小效应或归因要求高时重视科学AB；小规模、不成熟业务不宜负担不相称的平台成本，可先做成本合适的试用与观察。实际只有前后比较时就称前后观察，不改称随机AB；第4.7节案例属于前后观察，第2.6节也未披露可独立审计的随机化和统计细节。（4.7、6.6）

不把正向变化当显著、不把显著当达到业务目标、不把点击改善当营收改善。作者案例中5.4%对5%是相对8%、绝对0.4个百分点，虽作者报告显著仍不同于预设10%目标；原始计数图未核，不声称独立复算P值。5%阈值、样本数、90/5/5分流等均为案例设置，不能设为所有用户默认。（6.3）

**同源文章的交叉限定**：已读文章A05的结果汇总图明确说明其数据仅为示例参考、非真实数据。因此书第4章/该文章的25→11、50→70、4→8等不能作为独立实测成效，更不能拿来承诺增长。文章正文50→70对应添加参考资料页的环节，书文称付费口径不一致，须保留差异，不擅自统一。≥3指生成研究记录/研究报告的次数，不是上传参考资料数量。文章A05与图书审计ID A05是两种编号，引用必须写明来源类别。

分流与复核不能凭名称完成：ID不自动随机，AA一次不显著不证明完全同质，不同实验层不保证无交互，未预设的反复补样不能被包装成无条件有效的确认流程。详见 [experiment-checks.md](experiment-checks.md)，本文件不重复实验执行清单。

## 组织落地与第二曲线

第5章要求目标、权限、资源和协作相配；作者提出增长策略中心及产品/运营/数据分工，但不构成每家公司必须改组的处方。按实际能力安排，避免让无决策权的人承担不可控制的整体目标。ROI/LTV/CAC在书中有混用风险，报告须分别定义收益、成本、分母和周期。具体检查见 [organization-checks.md](organization-checks.md)。（第5章，C541—C545）

第7章的第二曲线探索需要先核现有产品价值、剩余市场与竞争、技术/政策等外部变化。五路径为现用户新需求、新地域、新人群、新服务模式、技术升级；按生命周期、操作链和场景发现相关需求，再检验假设。短期疲惫不等于第一曲线终结，技术或订阅转型也不保证增长。详见 [second-curve.md](second-curve.md)。（7.1—7.4）

## 引用案例时的统一边界

| 情况 | 报告应如何写 |
| --- | --- |
| 作者报告千万级增长、翻倍、3次阈值等 | 标注作者、产品情境及章节，不当成用户业务结果或通用参数 |
| 第2章及第3章虚构数据/曲线 | 只借推理结构，不生成真实象限、权重和阈值 |
| 原书称显著但无完整实验信息 | 保留作者报告身份，明确未独立复算，不升级因果证据 |
| 规划、设想或期待 | 不改写为已上线或已实现；包括AI快研侠部分功能/深夜免费设想、WPS AI和部分订阅成效 |
| 历史公司组织与案例 | 不称现行官方事实，不复制TikTok数字等未核细节，不使用性别偏好泛化 |
| 读者反馈、作者自述、后记背书 | 不当独立效果证明或成功率 |
| 书内工具、公众号、二维码 | 仅作资料记录；访问、发消息、提交数据另按用户授权执行 |

原书章末承认方法不保证每个方案有效。最终交付应呈现可追溯判断、少数策略、未知项与下一项验证；不因需要输出完整HTML而把未知字段填成确定结论。
