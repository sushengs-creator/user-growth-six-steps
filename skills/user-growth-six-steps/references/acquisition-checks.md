# 可选付费获客检查：来源约束版

## 何时进入

用户明确提出广告获客、投流效果、CAC、收入回收、代理协作或跨端转化问题时使用。此模块依据用户指定文章A06/A07，并可结合A08的数据拆解；它是图书六步的后续文章补充，不是第七步，也不把付费获客设为所有业务默认解法。

来源：同目录 `article-methods.md` 的 `WX-A06`、`WX-A07`，具体原文链接、日期及覆盖见 `source-catalog.json`；口径差异见 `method-differences.md`。这些是作者2025年的个人业务经历，不是当前平台官方规则。下面顺序和字段是Skill实施编排，不冒充作者现成模板。

每轮选择1—3个关键问题，先用已有报表/合同，不要求重复填表。未知数保持未知；没有明确用户授权，不开户、充值、调整预算、发布广告或替用户花钱。

## 1. 明确购买的结果与费用

要核对：业务目标、平台当前优化事件、可用现金、服务费、券使用门槛、代理责任与数据权限。用户通常需要付费、合格线索或价值用户，不能只因平台优化点击就把点击写成业务成果。

可问：

- “你们希望这笔花费换来哪一个具体业务结果？”
- “当前账面可用现金、服务费和券的限制分别是什么？”
- “平台优化的事件能与真实用户行为核对吗？”

退出条件：知道钱买什么、现金实际可用多少、事件是否可信。事件与结果不一致时先记录差距，不能把消耗和点击直接当增长。

## 2. 对齐人群、周期和经济性

最小表字段：获客cohort、渠道/终端、花费范围、点击/注册/付费事件及分母、观察起止、收入窗口、去重方法。成本和收入必须属于同一cohort、同一范围、同一周期。

可问：

- “当前CAC的分母是注册用户、付费用户，还是合格线索？”
- “收入均摊给全部获客用户，还是只均摊给付费用户？”
- “这批用户已经拥有完整的收入观察窗口吗？”

检查规则：

- 所谓ROI若仅为30日营收/广告花费，显示为“30日收入回收比”；不要称净利润率或整体盈利。
- 付费用户ARPU与注册CAC直接相除会混分母，先对齐，不隐藏转化率。
- 只有当点击与注册来自同一cohort且成本范围一致时，CPC/注册率才对应同口径获注册成本。近似历史数字不强行当精确等式。
- 自然内容、人力、模型推理及代理服务可能有实际成本；原材料未给时记未知，不自动视零，也不编金额。

退出条件：可以解释主要比率的分子/分母/窗口；否则先输出修正口径和补证任务，不给盈利结论。

## 3. 看质量、边际变化与跨端归因

依用户实际数据区分预算段、渠道、素材、意图、终端和后续价值。小预算平均值不代表放量后边际效果。

可问：

- “增加预算后，新增这部分用户的付费或合格线索情况怎样？”
- “哪些流量的用户意图与产品实际能力不匹配？”
- “跨端用户和付费能否识别为同一个身份？”

不要因注册便宜就认定最优，不因出现一个大客户线索就认定投放盈利。跨端承接是待验证策略，不在小程序与PC重复计新增/收入。平台、版位、周末/工作日与素材判断只用当前业务证据，不照抄作者历史顺序。

## 4. 将不确定性变成可控验证

写明：待证假设、可承受范围、观察窗口、事件核验方式、继续条件、停止条件、负责人。数值只来自用户约束与可用数据；没有依据时保持待定，不拿文章的预算、CAC或回收比当阈值。

出现快速消耗而目标事件几乎没有时，先核对事件记录、意图/素材、自动扩量和真实质量，再决定调整方向。不要未经证据指认作弊，也不要统一建议关闭所有自动策略。

可问：

- “这次验证能够承受的投入范围是什么？”
- “什么情况一出现，就应停止新增消耗并排查？”
- “若结果改善，需要什么证据才允许扩大覆盖？”

若只是前后观察，明确同期变化和因果限制。若要真实改动后台/花费，必须有用户明确授权；生成诊断或方案不等于获得执行授权。

## 5. 检查素材与协作

素材承诺、价格和实际收费/体验一致；不为了提高点击使用误导性承诺。代理协作按合同、可核验行为与结果评价，不推断所有代理动机。公开联系方式按用户选择，不在无证据时归因信息泄露。

具体平台目标、开关、准入、定向、回传、出价和优惠规则必须依据用户当前后台及官方资料。不能把2025年文章当现行操作事实，也不能为了“严格按材料”而无视版本变化。

## HTML交付

仍按主报告六步组织，渠道事项进入相关指标、核心杠杆、行动和验证字段；可附一张费用/口径/回收/归因/限制表。

必须区分已知事实、作者历史案例、本次推断和未决项。阶段性结果可以是“先修复事件口径”“先对齐成本分母”“按预算段观察质量”，不必强行给投/不投结论。
