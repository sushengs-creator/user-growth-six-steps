# 冻结评分量规：growth-ops-frozen-20261110-v1

本量规只交给协调者和独立评分者，不能进入任何执行者的提示词、可读目录或检索上下文。评分者不得参与当前产品修改。共同输入见 cases.json；本量规不允许在看到答案后修改权重、算式、硬失败或预期路由。新问题可另记为后续测试，不能倒改本轮标准。

## 1. 可比性与证据

- 三个条件：旧版 Skill、新版 Skill、无 Skill。相同模型及版本、推理配置、温度（如可配置）、系统约束、用户输入、工具权限、联网限制、每轮预算。逐项记下实际配置，不将“相同角色名称”当作配置一致的证据。
- 主案例各开新会话；G04 第二轮必须接续第一轮答案且不可预先暴露。其他案例互不共享上下文。无 Skill 条件不得获得六步法概要、模板或量规。
- 旧/新版条件只允许其各自 Skill 及明确依赖。除这项差异，不能给任何条件额外教程、数据、搜索结果、人工纠错或重试机会。若 Skill 缺少自身依赖，这是被测产品问题；若共同环境缺工具，这是环境问题，所有受影响条件等同重跑或标记不可比。
- 协调者保留每轮完整输入、答案、工具调用/返回、实际产物和失败原因。运行只完成口头回答不等于交付完成。文件系统应能证明文件真实存在；JSON 实际解析，HTML 确有本案例内容，二者数字和建议交叉核验。未做浏览器检查时只可声称文件/内容检查通过。
- 给评分者随机标签 A/B/C，隐藏版本名、Skill 源文和作者。仅保留判断业务和交付所需的工具证据。不要为盲评删除不利内容。评分结束再揭盲。
- 某条件偶发工具失败不得悄悄补救后当作首轮结果；记录首次结果，若重跑，采用同一规则重跑所有条件并另表报告。
- 不按“六步”“北极星”等词是否出现、字数、排版丰富度或模板字段数量给分。替代方案只要事实成立、可执行、契合约束，同样得分。提出问题本身不算质量，问题应能改变下一步选择。

## 2. 五个质量维度：每项 0–2 分

每个主案例每轮满分 10 分。每项必须附答案中的证据位置（文件/段落或 JSON 路径）和一条具体理由。整数评分，不用印象打小数。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| D1 事实、口径与因果 | 主要判断含实质算式/分母/人数与事件/观察窗错误，或凭空补事实、把非随机变化归因给方案 | 核心结论大体正确，但漏解释一个会影响复盘的口径或不确定性；没有硬失败 | 已知、未知、假设分清；与所选问题相关的算式和分母正确；不作超出证据的因果结论；无数据时保持未知 |
| D2 关键问题与范围 | 没选出可推动行动的问题；回答偏题，或用完整框架淹没明确局部任务 | 问题相关但优先级/依据较弱，或多列低价值问题，行动仍能找到 | 依据现有证据选最先验证的问题，说明为什么值得先做；无数据时用少量高信息问题缩小不确定性；尊重局部范围 |
| D3 行动可执行性 | 只给口号/原则，或行动依赖未获准的人力、预算、触达、开发能力 | 有具体动作但缺少执行对象、时间/工作量、操作方式或检查方式之一，运营还需补一次方案 | 在已有资源内能启动；谁/对谁、做什么、何时、记录什么足够明确；实验或观察有可判读结果及后续决策规则，无需新增重工程 |
| D4 不确定性与复盘适应 | 遇到缺失/冲突仍强行定论；用未成熟窗口报留存；多轮未修正被推翻的前提 | 承认不确定或更正数字，但未把它落实到行动/暂停结论；复盘修正不完整 | 把关键缺口、冲突或样本局限转为最小核查；区分当下可做与尚不能断言的事；多轮明确保留/撤回/更新，保留原限制 |
| D5 交付完整与一致 | 未形成真实可读的双文件，JSON 无法解析，或两种产物核心建议/数字矛盾 | 双文件可用且核心一致，但关键事实/待确认事项/行动/验证办法在一种格式中缺失或难以使用 | 实际 HTML 和合法 JSON 均可找到；包含已知、未知、判断、行动、验证所需内容，核心相互一致，方便运营者继续执行；无需固定字段名或视觉风格 |

“决策规则”可为定性核查、按事实修正或预先指定的方向性门槛；不要求凭空给出统计功效/显著性或假装一周必能检出效果。用于计划的样本目标或阈值，只要明确为拟定目标且未冒充历史事实，不因缺少外部依据直接硬失败。

## 3. 标准硬失败（单独记录，不被高总分抵消）

只标记明确出现且影响建议/交付的行为，记录原句、证据和类别；不要因关键词机械判罚。

- **H1 编造业务证据**：将输入中没有的历史规模、转化、访谈结果、已执行活动、已验证效果或统计显著性当作事实。清楚标注的假设/示例/计划值不属于此项。
- **H2 相关当因果**：在没有足以识别因果的证据时，宣布某版/动作造成增长或下降；包含用分渠道改善直接证明版本有效。允许报告观察差异、提出因果假设、附条件的暂行决策。
- **H3 用错分母或单位**：把事件次数当去重人数、订单数当付费用户，或者混用用户群体/观察窗并据此给出关键率、效果或决策。单纯省略与任务无关的附加比率不算失败。
- **H4 假文件/假验证**：声称文件已保存或已检查，但对应文件不存在、只有空模板/伪造链接，或声称发生了没有工具证据的渲染/校验。若如实承认环境失败，D5 记 0 并标环境问题，不追加“造假”。
- **H5 丢失关键限制**：最终建议直接依赖明确禁止的行为，例如 G01 私信/群发或开发、G02 删除表单字段/降价、G03 增加广告预算、G04 每天推送/超额人力。只是解释被禁止方案为何不合适不算；明确条件性远期备选也不因提及而硬失败，但不能作为本轮待执行动作。

某轮出现任何硬失败，该案例标记“不通过”，同时保留维度分数便于解释。一个条件出现硬失败，不得标记为本轮整体通过。后续纠正不抹去上一轮错误，但应给后续轮正确修正的分数。

## 4. 各案例核查锚点（评分专用，不给执行者）

这些是实质判断锚点，不是唯一答案。不得要求执行者复现某句文案、固定步骤或指定实验。

### G01：无数据初学者

- 无成员数、活跃/留存基线，不能填数字或声称哪一环已证实最差。
- 核心方向应围绕“持续完成练习”澄清目标行为、可见范围/取数条件、可动用触点等；最多 3 个先问问题，问题应有决策价值，不必恰好问 3 个。
- 方案在总计 6 小时/7 天、零预算、仅可见公开群发言且无后台的现实内启动。可建立最小手工观察记录；必须说明公开发言不是全量使用或练习完成的可靠替代，不强行计算全体成员留存。
- 可以给公开群内容/自愿反馈等动作，前提是不把“可查看”冒充“已获发言管理权限”。涉及尚未确认的权限时应附前提，并给纯观察即可启动的部分。不能等待回答而完全不交付。
- 有限样本/一周看不到因果效果，不等于无价值；验证是否能观察到目标行为、哪类信息最缺，也可得满分。

### G02：局部任务与分母

- 指定主指标为访客到试用注册转化，正确基线 **60/500=12%**。90 是提交次数，75 是提交人数，均不是完成试用注册人数。12 名付费与 15 笔订单不可互换。
- 不强制计算所有漏斗阶段；如计算，点击率 160/500=32%，提交率 75/500=15%，试用到付费人数比 12/60=20%，均须写清含义。目标指标不能被订单率悄悄替换。
- 恰当完成“一个标题及按钮、一个主要指标及当前值、两个当周动作”。不要因助手没展开六步而扣分；不需要重建全站或完整增长战略。
- 新文案具体、可理解，但不能凭空许诺未提供的产品功能、效果、免费政策或试用时长。可以采用中性试用表达并把具体价值主张列为待确认。
- 验证只动允许的页面文案/有限前端支持。不能建议删字段，即使它可能是合理的其他情境优化。

### G03：渠道混合与不可归因

- 旧版总计 140/3000≈**4.67%**；新版 160/4000=**4.00%**，下降约 **0.67 个百分点**。自然渠道 6%→7%；广告渠道 2%→3%，各上升 **1 个百分点**。总体与分组方向不同不构成计算矛盾，访客来源构成变化可解释这种现象。
- 付费人数 140→160 的增长不证明转化率上升。自然份额从 2/3 降为 1/4，低基线广告渠道权重提高；只报告这一构成效应仍不能隔离新版的作用。
- 两方的观察有事实部分，但两方“证明新版造成某结果”的推断均不成立：无随机分配，同期渠道活动/广告受众变化，渠道内人群也可能变化。
- 当前可做条件性的保留、受控回退或收窄试验，不能凭量规偏好强迫唯一上线决定；需把风险、业务需求与证据强度分开说清。
- 合格下一步可在同渠道同期作可实施的对照、先验证分流及埋点，或先核对可用切分能力后采用更弱的观察方案。不能要求工程半天必然搭成完整实验平台，也不能保证一周统计显著。观察方案必须保留“仍不能归因”的边界。

### G04：多轮修正、冲突证据和限制保持

第一轮仅按当时输入评分，不用第二轮事实倒扣：激活率 **400/1000=40%**，D7 **180/1000=18%**。5 人访谈可提出入口假设，不能证明它是总体主因。选入口可见性或优先核验数据都可接受，只要解释价值、设计小实验并满足限制。

第二轮必须纳入新证据：

- 已确认旧激活人数为 210，故旧激活率改为 **21%**；原 40% 需撤回。改后观察到 **46/200=23%**，68/200=34% 是事件/人数混算，不能作用户激活率。
- 23% 与 21% 的表面差为 **2 个百分点**，不是 9；且旧批完整观察与新批 3 天窗口尚未统一，不可直接宣布改版提升 2 个百分点，更不能承诺留存变好。
- D7 180 与 95 为尚未排解的冲突，不能默选一个为真或取平均当真值。可以分别报告 18%/9.5% 的争议口径，并具体核对 cohort ID、事件规则、去重/时区/日期等实际差异；不需要机械罗列所有可能性。
- 新批只有 3 天，D7 尚不可得。老用户访谈不足以直接验证新用户入口困难，需修正其证据权重。
- 首轮行动中仍有价值的部分可保留，但应明确为何保留、是否暂停全量结论、下一步怎样补齐证据。每天推送仍被禁止；负责人临时提议不能覆盖用户再次强调的限制。

## 5. 路由评分

路由单独报告，不混入正文质量 40 分。

- **R01：应选择被测增长运营 Skill**（有该 Skill 的旧版/新版条件）；用户明确要求定位增长问题并做运营验证。
- **R02：不应选择被测增长运营 Skill**；这是明确只要译文的翻译请求，业务词汇不足以触发流程。
- 有 Skill 条件各报告正确数 /2、误调用、漏调用以及调用依据。若仅靠模拟选择且无实际调用轨迹，只能称“入口描述路由检查”，不能称线上路由已验证。
- 无 Skill 条件不存在可选入口，路由记 N/A；不要将它算作 R01 漏调用，也不要与有 Skill 条件比较路由准确率。可保留其自然答复用于观察，但不替代质量测例。

## 6. 汇总、验收与结论边界

- G01–G03 各轮分数就是案例分。G04 两轮分别评分，案例分为两轮总分的平均值。四个案例等权，总分 **40 分**，可出现 0.5 分。另列每维案例平均、逐案例硬失败、文件检查和路由结果，不只报告一个总分。
- 本轮“基本可用”：零硬失败；5 轮全部真实双文件；每轮五维均不为 0；总分至少 **32/40**。这是这组有限场景的门槛，不代表生产验收。
- 对每个参照条件分别报告候选差值。预先将“本组测例出现明确改善”限定为：候选满足基本可用、总分至少高 **4/40**、至少 **2 个案例**改善、G03/G04 均不退步，且没有新增硬失败。没有达到则写“未展示明确改善”，不可把形式更丰富或一例变好写成总体提升。
- 若更高总分与新增硬失败同时出现，不能判“更好”。若参照硬失败而候选修复，可明确报告该类修复；不要把它等同于所有任务都会改善。
- 完整保留失败和不确定样本，不得删除难例、只比较精挑的输出、用新版生成的答案作标准答案，或用同一作者的自评宣称独立验证。
- 4 个主案例、2 个路由且单次运行最多支持“在这些固定输入、配置和工具限制下的表现”。它不能证明真实增长效果、普适因果诊断能力、跨行业覆盖、稳定多轮表现、统计显著优越、生产路由可靠或所有 HTML 渲染环境兼容。
- 随机性、隐藏的模型配置差异、文档版本/依赖、预算差异及环境失败是主要限制。若实际条件不一致，应先披露不可比项；不能用分数掩盖。若无独立盲评，明示为非盲/自评而降低结论强度。
