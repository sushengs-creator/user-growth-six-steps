# 用户增长6步法

**把“增长出了问题”推进为有依据的判断、可执行的行动和可复核的验证计划。**

这是一个用于 Codex 的用户增长诊断 Skill。它根据你已经提供的业务信息，围绕关键缺口逐步提问，梳理指标、动力、杠杆、候选行为阈值、策略和验证方式，最终交付 **HTML 增长诊断与行动验证报告，以及可编辑 JSON**。

## 最简单的安装方法

在 **Codex 对话框**里复制这一句：

```text
请使用 $skill-installer 安装 https://github.com/sushengs-creator/user-growth-six-steps/tree/main/skills/user-growth-six-steps ，完成后确认 Skill 可用。
```

安装完成后，在下一轮对话输入下方调用口令。如果当前窗口没有发现新 Skill，开启新对话后再调用。此方式无需你手动复制文件。

习惯终端的读者，可在希望使用 Skill 的项目目录执行：

```bash
npx -y skills add sushengs-creator/user-growth-six-steps --skill user-growth-six-steps -a codex -y
```

这条命令使用 [Skills CLI](https://github.com/vercel-labs/skills)，默认安装到当前项目；需要 Node.js 和 npm。想在所有项目中使用，可在命令末尾加 `-g`。本仓库只有一个 Skill，明确选择 Codex 即可。

Skill 生成报告需要运行环境可读写文件并执行 **Python 3**，生成器仅使用标准库，不需要额外 API Key。上述两个安装方式选一个即可。

## 调用口令

```text
使用 $user-growth-six-steps，帮我解决[你的增长问题]。请复用已有信息，每轮先问一个最关键的问题，最后交付 HTML 增长方案和 JSON。
```

例如：

```text
使用 $user-growth-six-steps。我们做小商户排班工具，很多人注册后没有发布第一张排班表，团队只有两天开发资源。请一步步帮我判断先改哪里，最后交付 HTML 方案。
```

把示例业务替换为你的真实情况。中文名称是“用户增长6步法”，准确的技术调用名是 `$user-growth-six-steps`。

## 读者怎样使用

1. **说清问题。** 告诉它你做什么、服务谁、增长卡在哪里；已知时间、预算或人员限制也一起说明。
2. **逐步补充证据。** 有报表、用户反馈或实验记录就直接提供。它通常每轮先问一个关键问题，最多1—3个，不要求重填已有信息。
3. **得到本轮可用的方案。** 数据不齐也可先交付草案；未知数保留未知，缺口会转成补证任务。
4. **执行后回来复盘。** 带着真实结果更新报告，判断继续、修改还是停止。换新对话时附上原来的 HTML 或 JSON。

已有明确的局部问题，例如“只核对实验是否支持推广”，可以直接进入相关步骤。只想简短核查时说“不需要HTML”；暂时不想回答时说“先基于已有材料交付草案”。完整口令见 [读者使用指南](docs/reader-guide.md)。

## 操作示范

以“新店注册后不完成首次盘点”为例，看怎样从提问走到行动草案。

下面是一段**虚构对话示范**，与仓库现有报告采用同一组材料；它展示使用方式，不是实际运行记录或真实增长成果。你可以照着表达，把产品、数字和约束换成自己的。

### 1. 复制口令，说出当前问题

```text
使用 $user-growth-six-steps。我们做小店库存管理工具，想改善新店注册后不完成首次盘点的问题。这一批有80家新注册店铺，每家都观察满7天，24家完成盘点。请每轮先问一个关键问题，最后交付HTML行动草案和JSON。
```

### 2. 逐轮补充信息，不必先写完整需求书

**第一轮：把“完成”说清楚。**

> AI：你们怎样判定一家店完成了首次有效盘点？
>
> 你：需要导入真实货品、录入实际库存，并确认盘点结果。按店铺去重，每家只计首次完成；24家都符合这个定义。

**第二轮：找优先调查的线索。**

> AI：未完成盘点的店主，具体在哪一步遇到了困难？
>
> 你：我们问过5位未完成者，其中3位说导入字段说明不清楚。还没有完整的导入、纠错、确认环节数据。

**第三轮：把建议接到实际分工。**

> AI：这轮排查与改进的人员安排确定了吗？
>
> 你：还没确定，开发工作量和实际排期也待确认。请先建议产品、开发和运营各自做什么，基于已有信息生成草案，缺少的数据列成待补项。

这时即可交付本轮报告，不必为了凑齐六步继续盘问。负责人和排期会标明是建议安排，留待团队确认。

### 3. 看懂报告：当前能判断什么

报告会把 **24÷80＝30%** 记为“7天首次有效盘点率”的虚构基线。这是本轮局部激活指标，**业务北极星仍待确认**。3位反馈者提供了调查线索，还不足以证明字段说明是主要流失原因。

六步状态会如实保留：北极星、增长模式待核对；核心杠杆正在调查；魔法数字因缺少行为与后续使用记录而暂受阻；策略尚待任务观察支持；验证尚未运行。

报告的行动节选如下：

| 先做什么 | 建议分工，待确认 | 怎样决定下一步 |
| --- | --- | --- |
| 观察导入、纠错、确认的任务过程，复核事件记录 | 产品负责人 | 区分字段不懂、资料未准备和操作故障；若主要障碍不同，调整方向 |
| 观察支持后，评估字段例子与导入预览 | 产品与开发 | 工作量确认后再排期；出现错导或错误确认时暂停并排查 |
| 回收口径可比的后续结果 | 运营或数据负责人 | 每店观察满7天后复盘；继续门槛需在上线前确定 |

**先安排排查和方案准备，取得实际结果后再判断是否增长。** 未取得随机对照数据时，前后变化只写成观察结果，不写成AB实验已验证有效。

查看这组材料对应的现成产物：[HTML报告](examples/growth-report.html)（下载后用浏览器打开）和[可编辑JSON](examples/growth-report.json)。报告包含当前判断、六步状态、事实与假设、缺口、指标、行动、验证安排及来源限制；这些文件也明确标注“公开演示、草案”。

### 4. 做完后，带着结果继续

把原JSON和真实观察记录附给Codex，再复制：

```text
使用 $user-growth-six-steps，继续这份增长草案。请读取我附上的原JSON和本轮观察记录，区分已确认事实与仍待验证的假设，判断应继续、修改还是停止原方案。不要补造未知数据；更新HTML和JSON，并说明这次改变了哪些判断。
```

如果只想核对某个结果，可以加一句“本次只回答这个问题，不需要HTML”。

## 六步方法论

六步主线来自卢壮华《增长杠杆：探索用户增长的6步法》。本 Skill 把这条判断链组织为对话和可执行报告；以下是每步要解决的实际问题。

| 步骤 | 核心问题 | 形成的产物 |
| --- | --- | --- |
| 1. 确定用户增长的北极星指标 | 什么增长代表用户与业务真正获得价值？ | 有行为、对象、周期和计数口径的指标卡 |
| 2. 认清合适的用户增长驱动模式 | 用户为什么来、留下、付费或带来其他人？ | 当前主导与辅助动力，以及支持证据 |
| 3. 确认用户增长的核心杠杆 | 在现有资源内，先改哪一处最值得？ | 少数优先机会及选择理由 |
| 4. 寻找用户增长的魔法数字 | 哪个行为阈值可能关联后续价值？ | 有数据支持的候选，或寻找阈值的采集计划 |
| 5. 基于魔法数字设计用户增长策略 | 怎样帮助目标用户完成有价值的行为？ | 人群、改动、资源、负责人和验证指标 |
| 6. 通过AB实验验证用户增长策略效果 | 结果支持什么判断，是否继续投入？ | 验证设计，以及取得真实结果后的阶段决定 |

这六步有几个关键连接：先确定目标，才知道应该优化什么；先找到杠杆，才有理由选择策略；行为与结果相关，只能产生候选假设，不能证明强制用户做到某个次数就有效；最后用与业务条件相称的验证支持决定。

**没有找到魔法数字时，也可以针对有证据的体验问题做探索。** 有限资源可以先安排低成本试用或观察；如果没有随机分组，就如实称为前后观察。局部激活率也不自动等于整体北极星。

详细的输入、判断、输出、常见误用和贯穿案例见 [用户增长6步法方法论](docs/methodology.md)。

## 最终交付什么产品

主要产品是一份 **增长诊断与行动验证报告**：

| 交付物 | 读者可以怎么用 |
| --- | --- |
| 单文件 HTML | 直接用浏览器打开，发给团队讨论，打印或在打印界面保存为PDF |
| 可编辑 JSON | 保存结构化判断，补数据后继续生成新版报告，无需读者手动编写 |

报告包含：当前判断、六步真实状态、事实与假设、信息缺口、指标口径、优先行动、负责人和时间、验证方案、继续或停止依据，以及来源和限制。HTML 内嵌样式，不依赖网络字体、CDN或外部脚本。

下载 [HTML示例](examples/growth-report.html) 后用浏览器打开；对应 [JSON输入](examples/growth-report.json) 可用于重新生成。示例为明确标注的虚构业务，展示数据不足时的草案形式。

```bash
python3 skills/user-growth-six-steps/scripts/render_report.py examples/growth-report.json growth-report.html
```

报告定稿表示本次文稿完成；实验、上线和业务收益需要真实实施，不能由报告状态替代。

## 这个 Skill 的价值

- **减少无效讨论。** 每个问题都服务于下一项判断，已有信息直接复用。
- **把建议连接到证据。** 区分用户事实、作者方法、历史案例和本次假设，数字与结论能追溯。
- **让行动可执行。** 明确先改变什么、由谁做、受什么资源限制，以及如何判断是否继续。
- **保留不确定性。** 缺数据时给出补证任务，不为完整表格编造阈值、样本或增长幅度。
- **留下可复用的产物。** HTML供团队阅读，JSON支持后续更新，减少下一次诊断重新开始的成本。

适合已有产品或服务的活跃、留存、转化与增长验证问题。若产品价值或商业模式尚不清楚，会先澄清这些前提；本资料不提供完整的广告平台操作教程。
