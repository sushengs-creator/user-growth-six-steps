# 用户增长6步法

**把增长问题说给智能体听，一步步找到先改什么、怎么做、怎样判断有没有用。**

注册的人多，但真正使用的人少？用户不回来，或不知道先改产品、转化还是获客？这个 Skill 会复用你已有的信息，每轮先问一个关键问题，最后整理成可以交给团队讨论的 **HTML 增长行动报告**。你不需要先懂增长术语，也不需要会写代码。

这是面向不同智能体的 **Agent Skills 技能包**，不是独立软件，也不限于 Codex。支持 Skills 的应用可以安装；能读取工作区文件的智能体可以临时加载。仅能聊天、不能读完整资料或生成文件的应用，能力另有限制，见[安装指南](docs/install-guide.md)。

**第一次使用，只做四件事：安装或加载 → 说出问题 → 回答追问 → 打开报告。**

[开始安装](#安装或加载) · [第一次怎么问](#开始第一次对话) · [完整操作示范](#操作示范) · [拿到报告后怎么用](#拿到报告后怎么用) · [常见问题](#常见问题) · [六步方法论](#六步方法论)

## 安装或加载

### 不熟悉命令：先把这段话发给你的智能体

适用于能够联网并管理本地或云端工作区的智能体。在你平时使用的应用里，直接复制：

```text
请帮我安装「用户增长6步法」：
https://github.com/sushengs-creator/user-growth-six-steps/tree/main/skills/user-growth-six-steps

先检查当前应用支持的 Skill 安装方式，再安装完整技能包。完成后请实际读取 SKILL.md 和相关参考文件，确认当前对话可以使用，并说明能否生成可下载的 HTML 报告。如果本应用不支持安装，请明确告诉我，给出这里可用的加载方法。
```

如果应用只能回答文字、无法下载或安装文件，就用下面的手动方法。**收到“已记住”不等于装好了；要确认它实际读到了技能文件。**

### 会用终端：一条命令，按提示选择自己的应用

在你希望使用 Skill 的工作文件夹内，打开终端并运行：

```bash
npx skills add sushengs-creator/user-growth-six-steps --skill user-growth-six-steps
```

需要已安装 Node.js 和 npm/npx。工具会显示检测到的智能体；确认是你使用的应用，按提示选择安装范围。选 **Project** 只在当前项目使用，选 **Global** 用于该应用的个人范围。不要照抄选择别人的应用，也不必给所有应用安装。命令来自 [Skills CLI](https://github.com/vercel-labs/skills)，支持范围以它当前显示的列表为准。

### 无法自动安装：下载后交给应用加载

直接[下载已打包的 Skill ZIP](https://github.com/sushengs-creator/user-growth-six-steps/raw/refs/heads/main/dist/user-growth-six-steps.zip)。应用有“上传 Skill”入口时，上传这个 ZIP；需要放入本地 Skills 目录时，解压后复制**整个 `user-growth-six-steps` 文件夹**。不需要自己重新打包，也不要只复制 `SKILL.md`，它还要读取配套参考文件。

不知道放在哪里？[跨平台安装指南](docs/install-guide.md)列出了已核验的目录、导入注意事项，以及不支持原生 Skills 时的工作区加载办法。本机安装不会自动同步到云端智能体，云端也需要能读到完整技能包。

### 安装后，确认当前对话已经能用

在新对话中发送：

```text
请检查你是否能使用「用户增长6步法」（user-growth-six-steps）。实际读取技能说明，告诉我读到的文件位置，并确认能否提供 HTML 文件或下载附件。先不要开始业务诊断；如果没有找到文件，请如实说明。
```

成功的标志是：它能指出实际加载的 `SKILL.md`，并说明报告交付能力。如果找不到，先按安装指南排查；仅复述本页介绍不能证明已加载。

## 开始第一次对话

复制下面这段，把方括号换成你的情况。**数字不知道就写“不知道”，不要为了使用 Skill 临时编数据。**

```text
请使用「用户增长6步法」（user-growth-six-steps）。
我做的是：[产品或服务]，主要用户是：[谁]。
现在的问题是：[一个具体的增长现象]。
已有材料或限制：[数据、用户反馈、时间、预算；没有就写暂时不清楚]。
请复用这些信息，每轮先问我一个关键问题，最后交付 HTML 行动草案和用于后续更新的 JSON。
```

还没整理数据，也可以只说：

```text
请使用「用户增长6步法」（user-growth-six-steps）。我们做面向小商户的排班工具，很多人注册后没有发布第一张排班表，暂时没有完整数据。请先带我判断需要了解什么，每轮只问一个问题。
```

上面是虚构业务示例，换成你的业务即可。**先用自然语言点名技能；`$` 不是所有应用通用的语法。** Codex 可用 `$user-growth-six-steps`；Claude Code 可用 `/user-growth-six-steps`；其他应用按它自己的技能选择方式调用。加载与调用是两步，单发名称不会自动完成安装。

接下来，回答它当轮的问题即可。有报表、反馈或现成方案就直接附上；它应先用这些材料，再问真正影响判断的缺口，不必让你从头重说。

资料暂时补不上、想先拿到能讨论的版本时，直接回复：

```text
我暂时没有更多数据。请先基于已有材料生成 HTML 草案和 JSON，标清事实、假设和待补资料，给出下一步最小行动。
```

不需要坚持聊满六步，也不保证固定三轮就能解决所有问题。材料充分时可以直接出报告；材料有限时先交草案。

## 操作示范

以“新店注册后不完成首次盘点”为例，看怎样从提问走到行动草案。

下面是一段**虚构对话示范**，与仓库现有报告采用同一组材料；它展示使用方式，不是实际运行记录或真实增长成果。你可以照着表达，把产品、数字和约束换成自己的。

### 1. 复制口令，说出当前问题

```text
请使用「用户增长6步法」（user-growth-six-steps）。我们做小店库存管理工具，想改善新店注册后不完成首次盘点的问题。这一批有80家新注册店铺，每家都观察满7天，24家完成盘点。请每轮先问一个关键问题，最后交付HTML行动草案和JSON。
```

### 2. 逐轮补充信息，不必先写完整需求书

**第一轮：把“完成”说清楚。**

> AI：你们怎样判定一家店完成了首次有效盘点？
>
> 你：需要导入真实货品、录入实际库存，并确认盘点结果。按店铺去重，每家只计首次完成；24家都符合这个定义。

**第二轮：找优先调查的线索。**

> AI：未完成盘点的店主，具体在哪一步遇到了困难？
>
> 你：我们问过5位未完成者，其中3位说导入字段说明不清楚。还没有完整的导入、纠错、确认环节数据。

**第三轮：把建议接到实际分工。**

> AI：这轮排查与改进的人员安排确定了吗？
>
> 你：还没确定，开发工作量和实际排期也待确认。请先建议产品、开发和运营各自做什么，基于已有信息生成草案，缺少的数据列成待补项。

这时即可交付本轮报告，不必为了凑齐六步继续盘问。负责人和排期会标明是建议安排，留待团队确认。

### 3. 看懂报告：当前能判断什么

报告会把 **24÷80＝30%** 记为“7天首次有效盘点率”的虚构基线。这是本轮局部激活指标，**业务北极星仍待确认**。3位反馈者提供了调查线索，还不足以证明字段说明是主要流失原因。

六步状态会如实保留：北极星、增长模式待核对；核心杠杆正在调查；魔法数字因缺少行为与后续使用记录而暂受阻；策略尚待任务观察支持；验证尚未运行。

报告的行动节选如下：

| 先做什么 | 建议分工，待确认 | 怎样决定下一步 |
| --- | --- | --- |
| 观察导入、纠错、确认的任务过程，复核事件记录 | 产品负责人 | 区分字段不懂、资料未准备和操作故障；若主要障碍不同，调整方向 |
| 观察支持后，评估字段例子与导入预览 | 产品与开发 | 工作量确认后再排期；出现错导或错误确认时暂停并排查 |
| 回收口径可比的后续结果 | 运营或数据负责人 | 每店观察满7天后复盘；继续门槛需在上线前确定 |

**先安排排查和方案准备，取得实际结果后再判断是否增长。** 未取得随机对照数据时，前后变化只写成观察结果，不写成AB实验已验证有效。

查看这组材料对应的现成产物：[HTML报告](examples/growth-report.html)（下载后用浏览器打开）和[可编辑JSON](examples/growth-report.json)。报告包含当前判断、六步状态、事实与假设、缺口、指标、行动、验证安排及来源限制；这些文件也明确标注“公开演示、草案”。

### 4. 做完后，带着结果继续

把原JSON和真实观察记录附给你使用的智能体，再复制：

```text
请使用「用户增长6步法」（user-growth-six-steps），继续这份增长草案。请读取我附上的原JSON和本轮观察记录，区分已确认事实与仍待验证的假设，判断应继续、修改还是停止原方案。不要补造未知数据；更新HTML和JSON，并说明这次改变了哪些判断。
```

如果只想核对某个结果，可以加一句“本次只回答这个问题，不需要HTML”。

## 拿到报告后怎么用

正常完成一轮方案整理后，你会拿到两份文件。下面的文件名只是示例，实际名称由智能体给出：

| 文件 | 你要做什么 |
| --- | --- |
| `growth-report.html` | 下载后双击，用浏览器打开。先看当前判断，再看优先行动、谁来做、什么时候复盘；可发给团队讨论或打印 |
| `growth-report.json` | 和 HTML 一起保存。它记录本轮判断，下一次发给智能体继续更新；你不用自己编写或编辑它 |

本地应用应给可点击文件，云端应用应给下载附件或可访问的文件链接。如果它只说“已生成”，却没有文件，继续说：

```text
请给我实际生成的 HTML 和 JSON 文件或下载附件，并检查文件确实存在。如果当前应用不能创建文件，请明确说明可用的交付方式，不要给不存在的链接。
```

先看一下产物长什么样：[HTML 报告示例](examples/growth-report.html) · [JSON 示例](examples/growth-report.json)。GitHub 通常显示 HTML 源码；点击文件页的 **Download raw file（下载原始文件）** 保存为 `.html`，再用浏览器打开即可。示例是虚构业务草案，不是真实增长成果。

**报告要帮你决定下一步，不要求你照单执行。** 与团队确认建议的分工和排期，选择当前有条件执行的行动。报告写好不等于实验已经跑完，也不代表增长已经实现。

完成一项行动后，把原 JSON 和真实记录交给智能体，复制：

```text
请使用「用户增长6步法」（user-growth-six-steps）继续这份报告。
我们执行了：[具体行动]。
实际结果是：[人群、时间、人数、完成情况和同期变化；不知道的保留未知]。
请判断哪些结论需要更新、下一步应继续、修改还是停止，并另存新版 HTML 和 JSON，保留上一版用于对照。
```

换新对话或换应用时，重新提供技能包或确认它已安装，再附上原报告。Skill 不会自动记住另一个应用里的聊天记录。

## 常见问题

| 遇到的情况 | 直接这样做 |
| --- | --- |
| 不知道该选什么指标，也没有完整数据 | 先讲用户是谁、卡在哪一步。回答“不知道”也可以；它会列补证任务 |
| 它一直追问，我想先看方案 | 回复“先基于已有材料交付草案，保留未知项” |
| 它开始泛泛讲增长，没有用我的信息 | 回复“请先读取技能文件，复用我已给的材料，只处理本次具体问题” |
| 我只想核对一个转化率或实验结论 | 回复“本次只回答这个问题，不需要 HTML”，不用重走全流程 |
| 输入技能名后找不到技能 | 先确认安装位置和当前工作区，重新开对话；仍找不到就按[安装指南](docs/install-guide.md)显式加载文件 |
| 应用不支持 Skills | 若能读工作区文件，按指南临时加载完整包；这不是永久安装。若只能聊天且读不到参考资料，只能做有限的方法体验 |
| 能读资料，但不能运行 Python | 仍可逐步诊断；能创建文件的应用可按相同内容规范直接生成 HTML/JSON，并注明未经过配套脚本校验 |
| 只能得到文字，拿不到下载文件 | 可以要求完整 HTML 源码，自己保存为 UTF-8 的 `.html` 文件；这是手动保存方式，不算智能体已交付文件 |

配套生成器只用 Python 标准库，不需要额外 API Key；安装与运行能力取决于当前智能体环境。各平台安装方式见[跨平台安装指南](docs/install-guide.md)，更多使用口令见[读者使用指南](docs/reader-guide.md)。

## 六步方法论

六步主线来自卢壮华《增长杠杆：探索用户增长的6步法》。本 Skill 把这条判断链组织为对话和可执行报告；以下是每步要解决的实际问题。

| 步骤 | 核心问题 | 形成的产物 |
| --- | --- | --- |
| 1. 确定用户增长的北极星指标 | 什么增长代表用户与业务真正获得价值？ | 有行为、对象、周期和计数口径的指标卡 |
| 2. 认清合适的用户增长驱动模式 | 用户为什么来、留下、付费或带来其他人？ | 当前主导与辅助动力，以及支持证据 |
| 3. 确认用户增长的核心杠杆 | 在现有资源内，先改哪一处最值得？ | 少数优先机会及选择理由 |
| 4. 寻找用户增长的魔法数字 | 哪个行为阈值可能关联后续价值？ | 有数据支持的候选，或寻找阈值的采集计划 |
| 5. 基于魔法数字设计用户增长策略 | 怎样帮助目标用户完成有价值的行为？ | 人群、改动、资源、负责人和验证指标 |
| 6. 通过AB实验验证用户增长策略效果 | 结果支持什么判断，是否继续投入？ | 验证设计，以及取得真实结果后的阶段决定 |

这六步有几个关键连接：先确定目标，才知道应该优化什么；先找到杠杆，才有理由选择策略；行为与结果相关，只能产生候选假设，不能证明强制用户做到某个次数就有效；最后用与业务条件相称的验证支持决定。

**没有找到魔法数字时，也可以针对有证据的体验问题做探索。** 有限资源可以先安排低成本试用或观察；如果没有随机分组，就如实称为前后观察。局部激活率也不自动等于整体北极星。

详细的输入、判断、输出、常见误用和贯穿案例见 [用户增长6步法方法论](docs/methodology.md)。

## 这个 Skill 的价值

- **减少无效讨论。** 每个问题都服务于下一项判断，已有信息直接复用。
- **把建议连接到证据。** 区分用户事实、作者方法、历史案例和本次假设，数字与结论能追溯。
- **让行动可执行。** 明确先改变什么、由谁做、受什么资源限制，以及如何判断是否继续。
- **保留不确定性。** 缺数据时给出补证任务，不为完整表格编造阈值、样本或增长幅度。
- **留下可复用的产物。** HTML供团队阅读，JSON支持后续更新，减少下一次诊断重新开始的成本。

适合已有产品或服务的活跃、留存、转化与增长验证问题。若产品价值或商业模式尚不清楚，会先澄清这些前提；本资料不提供完整的广告平台操作教程。
