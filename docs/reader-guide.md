# 用户增长6步法：读者使用指南

用一句话描述你的增长问题，Skill 就会从影响当前决定的关键缺口开始引导。你不需要先整理一份完整的增长报告，也不必熟悉所有增长术语。

**中文名称：用户增长6步法。技术调用名：`user-growth-six-steps`。** 第一次使用请先按[仓库首页](../README.md#安装或加载)安装或加载；不同平台的目录与入口见[跨平台安装指南](install-guide.md)。下面的自然语言口令适用于已经实际加载技能文件的智能体，名称本身不会自动安装技能。

> 当前为预发布版本：图书第1—7章正文、附录和后记已读完，部分图片待核；两个指定微信专辑共10篇独立文章，已读6篇，4篇待补。它会按已读范围引用，不将未读内容补成结论。

## 最简单的调用口令

复制这一句，把方括号内容换成你的问题：

```text
使用「用户增长6步法」（user-growth-six-steps），帮我解决[你的增长问题]。请复用我已经提供的信息，每轮先问一个最关键的问题，最后交付 HTML 增长方案。
```

例如：

```text
使用「用户增长6步法」（user-growth-six-steps）。我们做小商户排班工具，很多人注册后没有发布第一张排班表，团队只有两天开发资源。请一步步帮我判断先改哪里，最后交付 HTML 方案。
```

这是一段演示口令，其中的业务是虚构示例。使用时换成自己的情况即可。

## 最少准备什么

先说明这三件事就能开始：

1. **你做什么，服务谁。** 例如产品、服务或具体功能及其用户。
2. **你遇到什么问题。** 比如注册多但使用少、留存下降、转化停滞，或不确定一次实验该不该推广。
3. **你最关心的限制。** 如果已经知道，可以说明时间、预算、人员或不能改动的环节。

有数据时直接附上报表、用户反馈、指标定义或已有方案。能够说明人数、事件、时间窗口和数据来源，比只给一个百分比更有帮助。没有这些材料也可以开始，Skill 会把缺口列出来，先推进已有依据的部分。

如果你已经说明产品和目标，无须为调用 Skill 再写一遍。

## 对话会怎样推进

Skill 先提取已有的事实、目标与约束，再判断本次是完整诊断还是局部问题。需要完整诊断时，沿着原书六步推进：

| 步骤 | 你会得到什么 |
| --- | --- |
| 确定用户增长的北极星指标 | 核心价值与指标口径 |
| 认清合适的用户增长驱动模式 | 当前主要增长动力及依据 |
| 确认用户增长的核心杠杆 | 值得优先投入的少数机会 |
| 寻找用户增长的魔法数字 | 行为阈值候选，或寻找它的数据计划 |
| 基于魔法数字设计用户增长策略 | 有人群、改动、资源和负责人的行动 |
| 通过AB实验验证用户增长策略效果 | 与业务条件相称的验证和决策规则 |

它每轮只追问当前必要的1—3个短问题，优先问一个。你回答后，它会说明新增判断，再继续推进。未知数据不会被填成0，尚未验证的假设不会写成事实。

这不是必须完成的长问卷。你可以从已知问题进入某一步，也可以要求先交付草案。

## 四种常用口令

### 1. 继续已有诊断

在同一段对话中直接补充信息：

```text
继续使用「用户增长6步法」（user-growth-six-steps）。沿用前面已经确认的指标和业务背景。新增材料如下：[数据或反馈]。请更新受影响的判断，告诉我下一步先做什么。
```

换到新对话时，附上上次的报告、JSON 或必要背景：

```text
使用「用户增长6步法」（user-growth-six-steps），继续这份报告。附件是上次的 HTML 和 JSON，新增事实是：[变化]。请先读取已有结论，只复核被新事实影响的部分。
```

Skill 不保证自动记住另一段对话。把已有产物带到新对话，可以减少重复说明。

### 2. 只处理一个局部问题

```text
使用「用户增长6步法」（user-growth-six-steps）。这次只检查[指标口径/转化瓶颈/魔法数字/实验结果]。已有材料如下：[材料]。请直接处理本次问题，只补问会改变结论的前提，先用文字回答，不需要 HTML。
```

例如检查实验时，提供实际分组方式、每组人数、成功人数、观察窗口、事前目标和其他已知变化。Skill 会区分观察差异、统计证据和业务目标，不要求从业务介绍重新开始。

### 3. 数据不全，先拿到方案

```text
使用「用户增长6步法」（user-growth-six-steps）。我暂时没有更多数据，也不想继续回答。请基于现有材料先交付 HTML 草案和 JSON，分清事实、假设与缺口，写出最小补证任务，不要编造数字或把未完成步骤标成完成。
```

你会先得到可用的阶段产物。后续补齐数据，再更新同一份报告。

### 4. 复盘已经执行的行动

```text
使用「用户增长6步法」（user-growth-six-steps）。我们执行了报告中的[行动]，实际情况如下：[人群、时间、实施范围、结果与同期变化]。请判断哪些假设得到支持、哪些仍不能确认，更新继续、修改或停止的建议，并生成新版 HTML 与 JSON。
```

如果实际只有前后观察，直接说明即可。Skill 不会因为六步名称包含 AB，就把你的观察改写成随机实验。

## 最终会交付什么产品

当你需要完整方案或阶段报告时，主要产物是两份实际文件：

| 文件 | 用途 |
| --- | --- |
| 单文件 HTML 增长诊断与行动验证报告 | 用浏览器阅读、分享给团队、打印或在打印功能中保存为 PDF |
| 可编辑 JSON | 保存报告的结构化内容，便于补充数据后继续生成新版报告 |

HTML 包含内嵌样式，不依赖网络字体、CDN 或外部脚本。优先由智能体运行配套 Python 3 脚本生成；没有 Python 但能创建文件时，可按相同规范直接生成，并说明未经过配套脚本校验。只能输出文字时，应明确提供的是供手动保存的源码，不能声称已生成文件。JSON 面向后续更新，你无须手动学习或填写它。

本地应用应提供实际文件链接，云端应提供下载附件或可访问的文件链接。下载 HTML 后用浏览器打开，先看当前判断，再看优先行动与待补资料。保存 HTML 和 JSON，换会话时一并提供。GitHub 上的[公开 HTML 示例](../examples/growth-report.html)需要点击 Download raw file 下载，才能作为网页打开。

如果应用只说“已生成”却没有文件，回复“请提供实际 HTML 与 JSON 文件或可下载附件；如不能创建文件，请说明具体限制”。

报告会清楚呈现：

- 当前最重要的增长判断，以及它的证据强度。
- 六步分别进行到哪里；未涉及、待补资料的步骤保持真实状态。
- 已知事实、待验证假设和影响决策的信息缺口。
- 指标定义、对象、周期、分子分母与已知数值。
- 优先行动、负责人、范围、时间，以及继续或停止的依据。
- 验证方法、还需取得的数据、来源及结论限制。

仅有方案时，第6步不会显示实验已经完成。报告标记“定稿”，只表示本次文稿已经完成，不表示增长已经实现。

简短的指标或实验核查可以只交付文字；明确要求其他形式时，也不强制生成 HTML。

## 怎样得到更有用的结果

把“帮我提高增长”改成一个带对象和现象的问题，例如“新注册商户建完表但没有发布，先改哪一步”。如果已经决定本周只改善发布入口，就直接说明，Skill 会在这个范围内工作。

把证据与解释分开提供，例如“20家成功发布”是记录，“他们可能看不懂入口”是待验证解释。对于同一指标，尽量说明统计对象和时间，避免把用户数、次数、商户数混在一起。

如果不确定一个数字是否来自真实数据，直接标注“不确定”。Skill 可以帮助核查依据；它不能把作者案例、演示数据或其他产品的阈值变成你的经营事实。

这份 Skill 帮你形成**有依据的判断、可执行的行动和可复核的验证计划**。产品改动、实验运行和经营收益需要在真实业务中实现；它交付的报告是推动这些工作的工具。

想了解每一步的判断逻辑和贯穿示例，阅读 [用户增长6步法方法论](methodology.md)。
